# Загрузка фотографий локальным агентом

Инструменты предназначены для загрузки JPEG с компьютера администратора в существующее
мероприятие и существующую папку. Исходные файлы остаются на компьютере без изменений.
MCP читает сведения о мероприятиях и пакетах; передачей управляет отдельный CLI процесс.
Решение о полномочиях и разделении компонентов: [ADR 0085](../adr/0085-personal-tokens-and-local-agent-upload.md).

## Установка и вход

Нужны Python 3.12 или новее, `pipx` и доступное системное хранилище секретов.
Из checkout репозитория с этой версией выполните:

```bash
pipx install ./src/agent_client
findme auth login https://photos.example.com
findme auth status
```

В команде входа укажите фактический HTTPS origin вашего экземпляра FindMe Photo.
Вход запрашивает токен в интерактивном терминале без отображения введённого значения.
Команда `findme auth logout` удаляет локальный профиль и секрет из keyring.
Для нескольких экземпляров или учёток используйте `findme --profile NAME ...`;
по умолчанию профиль называется `default`.

## Персональный токен

В Django Admin войдите своей учётной записью, создайте именованный персональный токен для
этого компьютера и скопируйте показанный секрет. Он показывается один раз. Сервер хранит
только хеш; потерянный секрет нужно заменить новым токеном. Срок нового токена — 90 дней.

Владелец токена должен быть активным staff-пользователем. Токен не добавляет полномочий:
чтение и загрузка требуют обычных Django permissions, пакеты сохраняют существующие границы
владения. Для загрузки нужно `ingestion.upload_photos` и включённый серверный приём фото.
Суперпользователь получает права стандартным механизмом Django.

Секрет вводится через интерактивную команду входа и хранится системным keyring. Не вставляйте
его в задачу агенту или аргументы команды. Удаление локального профиля не заменяет серверный
отзыв: ненужный или раскрытый токен отзовите в админке. Изменение прав, блокировка учётки,
истечение срока или отзыв токена запрещают следующие API запросы.

## Команды загрузки

Сначала агент через MCP выбирает точные ID мероприятия и существующей папки.
Затем выполняет проверку и запуск, например:

```bash
findme upload inspect '/Photos/Осенний забег'
findme upload start '/Photos/Осенний забег' --event 42 --folder 7
```

ID в примере условные. Если `--folder` не указан, фотографии попадут в «Без папки».
Папка обходится рекурсивно; символические ссылки пропускаются. Одна задача отправляет
все выбранные JPEG в одно назначение. `inspect` не требует входа и не создаёт серверный пакет.
`start` проверяет назначение и лимиты, сохраняет задачу и запускает независимый процесс.

Команда возвращает JSON с ID локальной задачи. Используйте этот ID для управления:

```bash
findme upload status TASK_UUID
findme upload stop TASK_UUID
findme upload resume TASK_UUID
```

`TASK_UUID` замените значением из `start`. `status` возвращает локальный прогресс и доступное
серверное состояние; серверный UUID пакета используется инструментами MCP.
`failed_files` содержит первые 100 ошибок с полными локальными путями и кодами;
`failed_files_truncated` показывает, что список неполный. Полный перечень локальных ошибок
остаётся в manifest задачи; постраничный MCP `list_items` показывает все серверные элементы. Ошибки CLI
возвращаются как JSON с ненулевым кодом завершения. `stop` кооперативный: остановка происходит
на безопасной границе передачи, а уже принятые оригиналы сохраняются. Повторный `resume`
не должен создавать второго одновременно работающего отправителя этой задачи.

Данные клиента находятся в `$XDG_DATA_HOME/findme-photo` или `~/.local/share/findme-photo`.
Профиль хранит адрес сервера, SQLite manifest — файлы и прогресс; секрет остаётся в keyring.
Не удаляйте данные задачи до окончания передачи: они нужны для продолжения того же пакета.

## Подключение MCP

Настройте локальный stdio MCP в своём агенте:

```json
{
  "mcpServers": {
    "findme-photo": {
      "command": "findme",
      "args": ["mcp"]
    }
  }
}
```

Это пример распространённой формы конфигурации; название файла и обёртка зависят от агента.
Если агент не видит `findme` в PATH, укажите полный путь к установленному исполняемому файлу.
Для именованного профиля используйте `"args": ["--profile", "NAME", "mcp"]`.
Токен в конфигурацию MCP добавлять не нужно: используется ранее настроенный профиль.

Доступны инструменты `list_events`, `get_event`, `list_folders`, `list_batches`, `get_batch`,
`list_items`. Списки постраничные: `page` начинается с 1, ответ содержит `results` и
`next_page`. `get_batch` разделяет `originals` и `processing`. MCP не изменяет данные;
для запуска и управления передачей агент использует CLI.

Пример задачи агенту: «Найди мероприятие Осенний забег, выбери папку Финиш, проверь
`/Photos/Осенний забег` и запусти загрузку. Сообщи ID задачи, назначение и число файлов».

## Что означает завершение

«Оригиналы приняты» означает подтверждение сервером каждого файла пакета. После этого локальную
передачу можно завершить, даже если сервер ещё готовит галерею или выполняет распознавание.
Состояние обработки показывается отдельно. Ошибка обработки уже принятого фото не требует
повторной передачи оригинала.

Закрытие чата и терминала не останавливает фоновый процесс. Во время сна компьютера передача
приостанавливается; после перезагрузки нужна команда возобновления. Остановка задачи не
удаляет принятые фото. При возобновлении подтверждённые сервером файлы пропускаются.

## Границы первого выпуска

- Локальный клиент для macOS/Linux; без автозапуска после перезагрузки.
- Только JPEG, в рамках действующих серверных лимитов.
- Одна папка назначения на задачу; мероприятия и папки создаются через существующий GUI.
- MCP работает по stdio и только читает; постоянный сетевой MCP сервер не разворачивается.
- Данные задач хранятся локально, состояние принятых оригиналов — на сервере.

## Выпуск и откат

Клиент используется с версией приложения, содержащей agent API. Обычный release приложения
применяет additive migrations до запуска нового web. Новый серверный worker и облачные ресурсы
не нужны. После выпуска создайте токен, выполните проверку входа и пробную загрузку малого
пакета с последующим просмотром серверного статуса.

Откат web не удаляет оригиналы и существующие пакеты. До исправления клиента остановите
локальную задачу; при необходимости отзовите токен. Новые таблицы токенов и связей можно
оставить в БД при откате web. Автоматически удалять данные загрузки не требуется.
