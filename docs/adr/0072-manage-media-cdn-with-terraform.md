# 0072 Управлять медиа CDN через Terraform

- Status: Accepted
- Дата: 2026-11-20
- Авторы решения: владелец проекта
- Связанные решения: [ADR 0057](0057-declarative-cloud-infrastructure.md),
  [ADR 0069](0069-serve-media-through-cdn-without-imgproxy.md) и
  [ADR 0071](0071-prepare-photo-archives-in-background.md)

## Контекст

`img.findme-photo.ru` обслуживает обложки, превью и оригиналы по разным правилам.
Правило ZIP появилось в коде приложения и в скрипте настройки CDN. Инфраструктурный выпуск
не применял скрипт, поэтому действующий CDN отвечал на запрос ZIP общим правилом с кодом 404.

Штатный провайдер Yandex поддерживает группы источников. В используемой версии он не
поддерживает правила CDN и TLS-профиль, а при импорте существующего CDN предлагает обновить
привязку источника.

## Рассмотренные варианты

1. Выполнять скрипт настройки CDN отдельным шагом Infrastructure. Изменения правил при этом
   отсутствуют в плане Terraform.
2. Использовать провайдер Terraform для CDN-ресурса и правил. План показывает изменения
   маршрутизации, HTTPS и кеширования вместе с остальной инфраструктурой.

## Решение

Используем второй вариант. Провайдер FindMe читает состояние CDN-ресурса и правил через API
Yandex Cloud, поддерживает импорт и ожидает завершения операций записи. Группы источников
ведёт штатный провайдер Yandex. Infrastructure собирает провайдер из исходников репозитория и
проверяет контрольную сумму пакета по lock-файлу. Работа выполняется через сохранённый план и
его обычное подтверждение. У конфигурации CDN один владелец — Terraform.

Приложение получает секреты подписи и доступа к источнику из Lockbox. При обновлении правил
провайдер сохраняет действующие значения из API CDN. При создании правила ZIP он читает
ключ подписи действующего правила превью того же CDN. Поэтому Infrastructure выпускает
изменения правил со своей существующей OIDC-учёткой и ролью CDN. Для первичной настройки
подписанных правил и согласованной ротации предусмотрены ephemeral переменные и write-only
атрибуты. Значения секретов не записываются в Terraform state или сохранённый план.

## Проверка и откат

Действующий ресурс, группы и правила принимаем в state отдельным планом импорта без
действий записи в CDN. Следующий инфраструктурный план добавляет правило архивов. Перед
публичным включением проверяем обложки, превью, оригиналы и ZIP через действующий домен.
Процедура проверки и отката описана в [runbook](../runbooks/gallery-image-delivery.md).

## Последствия

План обнаруживает расхождения в настройках управляемых ресурсов CDN. Ключи остаются в
Lockbox. Проект поддерживает небольшое расширение API Yandex Cloud и его сборку, пока
штатный провайдер не сможет импортировать и вести все используемые настройки.
