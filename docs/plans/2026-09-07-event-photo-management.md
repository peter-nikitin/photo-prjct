## Rollback

Before any photo has been hidden, restoring the previous application image is safe for visibility;
retain the additive column rather than dropping data. Folder assignments already made remain valid.

After any hidden value exists, an image that ignores `is_hidden` is **not** a safe rollback: it
would republish suppressed photos. Use a corrective release that removes/disables the broken
workspace surface while retaining the Catalog field and suppression on every public authorization
path. Preserve purchased authorization, orders, assignments, processing state and all storage bytes.
Do not unhide photos or reverse the migration as a rollback shortcut. This release adds no
compatibility shim and does not authorize physical cleanup.
