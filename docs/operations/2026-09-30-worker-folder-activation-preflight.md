## IAM consequence

The current folder has the canonical VM and its database disk. Yandex Cloud documents that an Instance Groups manager must have `compute.editor` on the **folder containing its group**, and that the manager account must be in that same folder. In the current folder this would grant management of the canonical VM and disk; the selected separate worker folder avoids that grant. Current cloud/folder binding lists contain no worker-manager account because the worker folder/account have not been created. A future exact effective-access review must include inheritance from the organization/cloud and resource-scoped VPC/Lockbox grants, not only direct folder bindings.

Sources: [Instance Groups access](https://yandex.cloud/ru/docs/compute/concepts/instance-groups/access), [Compute role reference](https://yandex.cloud/ru/docs/iam/roles-reference), [multi-folder VPC](https://yandex.cloud/ru/docs/vpc/tutorials/multi-folder-vpc).

## Updated public tariff calculation, not an invoice

The public Yandex Cloud RUB catalogue was read for **2026-09-30**. Its relevant active SKUs remain: regular `standard-v3` CPU 1.24 RUB/vCPU-hour and RAM 0.33 RUB/GiB-hour; preemptible CPU 0.34 and RAM 0.083; `network-ssd` 0.0199 RUB/GiB-hour; retained image 0.0051 RUB/billed-GiB-hour; NAT gateway 0.39528 RUB/hour. The published Lockbox example lists 0.0274 RUB per secret-version-hour. These public rates include VAT for the Russian contract; account-specific discounts, grants, commitments, and billed image size were not inspected.

At the approved 2 vCPU / 8 GiB / 32 GiB SSD per worker, selfie regular compute plus disk is **5.7568 RUB/hour**; bulk preemptible compute plus disk is **1.9808 RUB/hour**. At a comparison 730-hour month, one NAT gateway and one worker-only secret version add 308.56 RUB. Thus an idle settled fleet with one selfie and no bulk is approximately **4,511 RUB/month incremental**, while a continuously present initial `1+1` is approximately **5,957 RUB/month incremental**, before billed worker-image size, retained extra secret versions, traffic, diagnostic samples, and temporary builder/replacement costs. This is unchanged from the [2026-09-28 detailed model](../research/2026-09-28-worker-pool-activation-cost.md), but the listed public rate inputs were rechecked today. The existing main VM's cost does not decrease in this stage. A separate folder does not by itself make worker compute or disks free.

SSD allocated with two workers would be 100 + 2 × 32 = **164 GiB**; one serial replacement would be **196 GiB**; a simultaneous 32 GiB builder would reach **228 GiB**, within the observed 256 GiB quota but still requiring bounded spend approval and complete disk inventory. Four worker disks plus a builder would reach **260 GiB** and exceed the quota; the approved cap-one serial-release protocol must never create that state. Builder cleanup before replacement remains the reviewed operational gate, not a claim that the present quota mathematically requires it. Idle bulk-zero savings require actual VM and boot-disk deletion, not a stopped or retained disk. Initial group creation warms both workers even if bulk demand is empty.

The public catalogue is [Yandex Compute pricing](https://yandex.cloud/ru/docs/compute/pricing) and [VPC pricing](https://yandex.cloud/ru/docs/vpc/pricing); [Lockbox pricing](https://yandex.cloud/ru/docs/lockbox/pricing) documents the secret-version unit. The unauthenticated public catalogue response used for active Compute SKUs is [dated 2026-09-30](https://yandex.cloud/api/priceList/getPriceList?installationCode=ru&currency=RUB&lang=ru&services%5B%5D=dn22pas77ftg9h3f2djj&withExpired=false&withThresholds=true&pageSize=1000&from=2026-09-30&to=2026-09-30); the [VPC response](https://yandex.cloud/api/priceList/getPriceList?installationCode=ru&currency=RUB&lang=ru&services%5B%5D=dn21qssbrdtcaus362kp&withExpired=false&withThresholds=true&pageSize=1000&from=2026-09-30&to=2026-09-30) contains the NAT SKU.
