# Дополнить покрытие расчёта стоимости инфраструктуры ЯО

Дата: 2026-10-25. Статус: future, не блокирует восстановление сайта.

Для инфраструктурного CI выбран готовый [terraform-yc-cost-estimation](https://github.com/terraform-yc-modules/terraform-yc-cost-estimation). Он покрывает VM, диски и зарезервированные публичные IP, но не включает Network Load Balancer и обработанный им трафик, Object Storage, CDN и KMS. Для текущего восстановления NLB и его трафик оцениваются вручную по [официальному тарифу Yandex Cloud](https://yandex.cloud/en/docs/network-load-balancer/pricing); прочие неподдержанные продукты остаются отдельными строками ручной проверки.

На первом этапе CI использует существующие возможности пакета. Terraform plan адаптируется для inline boot disk и не считает резервный публичный адрес одновременно как standalone address и NAT той же VM. Модель предполагает работу VM 24/7; прежняя VM сейчас остановлена, и её импорт не запускает её. Это оценочное допущение, а не утверждение о фактическом начислении за остановленную VM. Ресурсы, период работы которых upstream не моделирует, и неподдерживаемые продукты перечисляются в отчёте как ограничения, а их стоимость проверяется отдельно до одобрения plan. Они не учитываются как бесплатные и не скрываются из отчёта. Поэтому отсутствие автоматизации полного расчёта не блокирует первоначальное восстановление.

Триггер возврата к задаче: регулярные инфраструктурные изменения, при которых ручной расчёт NLB, его трафика, Object Storage, CDN или KMS становится частым источником задержек или ошибок. Тогда проверить актуальное покрытие upstream и добавить только нужное покрытие, предпочтительно вкладом в пакет, сохранив небольшую CI-интеграцию в проекте.

Результат: отчёт по текущему и планируемому состоянию с разницей в рублях, явными допущениями по времени работы, хранению, запросам и трафику. Для непредсказуемого потребления указывается сценарная оценка, а не обещание точного будущего счёта. Тарифы получать из официального [Billing API SKU](https://yandex.cloud/en/docs/billing/api-ref/Sku/list); неизвестные параметры и ресурсы должны оставаться видимыми. Проверить расчёты на наших конфигурациях, включая временное дублирование S3 при переносе, и исключить отправку Terraform plan с секретами во внешний демонстрационный сервис.
