# 0085: Персональные токены и локальная загрузка агентом

- Status: Accepted
- Date: 2026-11-22
- Deciders: владелец проекта; персональные токены с правами учётки и первая версия
  локальных инструментов явно согласованы в чате перед поручением реализации.
- Supersedes: none
- Superseded by: none

## Контекст

Агент на компьютере фотографа должен передавать оригиналы в существующее мероприятие.
Браузерная загрузка требует открытой страницы. Агенту нужны сведения о назначении и ходе
приёма, а передача должна переживать закрытие чата и терминала.

## Рассмотренные варианты

1. Персональный токен, локальный stdio MCP для чтения и самостоятельный CLI загрузчик.
2. OAuth с браузерным входом и обновлением доступа: удобнее для массового подключения,
   но добавляет сервер авторизации и новый жизненный цикл доступа.
3. Автоматизация GUI: зависит от сессии браузера и не обеспечивает независимую передачу.

## Решение

Выбран первый вариант. Токен идентифицирует существующую Django учётку; права и object ownership
проверяются заново при каждом запросе. Отдельной системы ролей и token scopes нет. Первый
выпуск доступен только активным staff-пользователям. Секрет показывается один раз, сервер
хранит хеш; отдельный токен можно отозвать. Создание и отзыв выполняются через Django Admin.

Локальные MCP и CLI используют общий профиль, секрет хранится системным keyring. MCP работает
по stdio и только читает доступные мероприятия, папки и состояния пакетов. CLI управляет
независимым локальным процессом и приватным manifest, не содержащим токена или storage grants.

Новый token-only HTTP API сохраняет существующие ingestion services и их права. Байты идут
напрямую в закрытое хранилище по ограниченному grant согласно ADR 0013. Django control plane
остаётся request-driven согласно ADR 0014; новый серверный broker/worker не требуется.
После приёма используется существующая обработка ADR 0017. Состояние приёма оригиналов и
состояние обработки различаются. Исходные локальные файлы не изменяются.

## Последствия

Один механизм полномочий обслуживает браузер и инструменты, отзыв прав действует сразу на
следующем запросе. Отдельный токен на устройство даёт независимый отзыв. Администратор
однократно переносит секрет в keyring. Сон компьютера приостанавливает передачу, после
перезагрузки требуется явное возобновление. Ошибки keyring не обходятся хранением открытого
секрета. CLI поддерживает локальную блокировку задачи и сверку подтверждений с сервером.

## Проверка

Проверяются отзыв, срок, блокировка учётки, текущие Django permissions и границы владения;
обычная browser session не даёт доступа к token API. Проверяются полный путь JPEG до
подтверждения, потеря ответа, остановка/возобновление и изменение локального файла.
Операционные команды и установка описываются в runbook, без зависимости от временного плана.
