# Дополнить покрытие расчёта стоимости инфраструктуры ЯО

Дата: 2026-10-25. Статус: future, не блокирует восстановление сайта.

Для инфраструктурного CI выбран готовый [terraform-yc-cost-estimation](https://github.com/terraform-yc-modules/terraform-yc-cost-estimation). По опубликованному списку он поддерживает VM, диски и публичные IP, но не перечисляет используемые FindMe Photo NLB, Object Storage, CDN и KMS. Поддержка нужных параметров и точность расчётов ещё должны быть проверены при интеграции; выбор пакета не означает завершённой проверки.

На первом этапе CI использует существующие возможности пакета. Неподдерживаемые ресурсы перечисляются в отчёте как нерассчитанные; перед ручным разрешением apply их стоимость оценивается отдельно по официальным тарифам. Они не учитываются как бесплатные и не скрываются из отчёта. Поэтому отсутствие автоматизации полного расчёта не блокирует первоначальное восстановление.

Триггер возврата к задаче: первое изменение NLB, Object Storage, CDN или KMS после первоначального восстановления, требующее повторного ручного расчёта. Тогда проверить актуальное покрытие upstream и добавить только оставшиеся необходимые расчёты, предпочтительно вкладом в пакет, сохранив небольшую CI-интеграцию в проекте.

Результат: отчёт по текущему и планируемому состоянию с разницей в рублях, явными допущениями по времени работы, хранению, запросам и трафику. Для непредсказуемого потребления указывается сценарная оценка, а не обещание точного будущего счёта. Тарифы получать из официального [Billing API SKU](https://yandex.cloud/en/docs/billing/api-ref/Sku/list); неизвестные параметры и ресурсы должны оставаться видимыми. Проверить расчёты на наших конфигурациях, включая временное дублирование S3 при переносе, и исключить отправку Terraform plan с секретами во внешний демонстрационный сервис.
