# 0079: Завершать включённую проверку одежды до публикации выдачи

- Status: Accepted
- Дата: 2026-11-20
- Авторы решения: владелец проекта; явный выбор автоматического повтора и ошибки вместо частичной выдачи
- Заменяет: [ADR 0077](0077-separate-appearance-processing-and-search-rollout.md) только в части успешной публикации лицевой выдачи при ошибке включённой стадии одежды
- Заменено: нет

## Контекст

Поиск по одежде может дополнять результаты лиц и сохранять рекомендации проверить найденные
кадры. Если включённая стадия не выполнилась, выдача только по лицам не соответствует ожидаемой
проверке. Успешный статус скрывает отсутствие части алгоритма и мешает оценивать его качество.

## Мотивы

- Отличать полностью выполненный поиск от сбоя одного из его включённых этапов.
- Автоматически повторять временный сбой, ограничивая нагрузку и время ожидания.
- Сохранять независимость переключателей распознавания и поиска.

## Рассмотренные варианты

1. Успешно публиковать лицевую выдачу без завершения включённой стадии одежды.
2. Публиковать лицевую выдачу с предупреждением об отсутствии проверки одежды.
3. Повторять поиск после ошибки стадии одежды и показывать ошибку при исчерпании попыток.

## Решение

Выбран вариант 3. Если проверка одежды включена для запроса и поиск имеет пригодный лицевой
корпус, успешное завершение требует выполнения этой стадии и сохранения её решений.
Пустые опоры или отсутствие кандидатов являются нормальным результатом проверки, а не ошибкой.
При выключенной функции выполняется обычный поиск по лицам. В состоянии `staff` это также
относится к запросам пользователей без staff-доступа; состояние `on` включает проверку для всех.

Ошибка вычисления или публикации решений одежды не публикует частичную выдачу. Исполнитель
переиспользует существующую очередь и её ограничение попыток: допускает один автоматический
повтор, затем завершает поиск явной ошибкой. Повтор использует исходный запрос. Новые задания
или независимый цикл повторов не создаются. После перезапуска исполнителя действует прежнее
восстановление очереди со сбросом счётчика; дополнительные повторы в этом случае допустимы.
Общие сроки действия запроса и бюджеты SQL остаются ограниченными. Причины для диагностики не содержат векторов, SQL с параметрами
или подписанных URL.

Флаги не изменяются из-за ошибки запроса. Ошибка одного поиска не выключает функцию для
следующих. Сохранённые ранее результаты остаются неизменяемыми снимками. Правила сравнения
внешности и применения рекомендаций эта запись не меняет.

## Последствия

### Положительные

- Успешная выдача означает выполнение включённого алгоритма.
- Повтор может устранить временный сбой без нового действия пользователя.
- Отказ этапа виден как незавершённый поиск вместо неотличимой частичной выдачи.

### Отрицательные

- Ошибка одежды временно лишает пользователя и уже вычисленных совпадений по лицу.
- Повтор увеличивает задержку и нагрузку; число попыток и срок действия запроса ограничены.

## Проверка и откат

Проверить первый сбой с последующим успехом, повторный сбой, атомарный отказ сохранения решений,
исчерпание срока запроса, успешный результат без опор, а также неизменный путь при off и для
пользователя без staff-доступа. Не сохранять частичные результаты и не публиковать готовность
при незавершённой обязательной стадии. Для возврата к поиску только по лицам выключить
`apparel-search-expansion` через Admin; существующие результаты и признаки сохранить.
