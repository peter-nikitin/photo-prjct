## Контекст

После разделения бакетов готовые превью и обложки хранятся в бакете медиа мероприятий.
Оригиналы находятся в отдельном приватном бакете. Чтение фото по прямым ссылкам обращается
к Object Storage в обход существующего CDN. Прежний источник CDN выполнял уменьшение
изображений на отдельной ВМ. Текущая задача — сократить повторные чтения из Object Storage.

## Варианты

1. Восстановить imgproxy и расширить число обслуживаемых путей. Сохраняется уменьшение при
   выдаче, но возвращается отдельный источник и вычислительная нагрузка.
2. Отдавать все изображения через Django при промахе. Подпись источника S3 не нужна клиенту,
   но холодные просмотры галерей создают поток запросов и байтов через ВМ приложения.
3. Отдавать готовые обложки и превью прямо из S3 при промахе CDN, а приватные оригиналы
   читать через Django. На ВМ попадают только промахи по оригиналам.

## Решение

Используем третий вариант на существующем `img.findme-photo.ru`. Обложки читаются из
`event-covers/` с публичным доступом по точному ключу. Готовые превью, включая предусмотренные
политикой водяные варианты, читаются из `previews/` без преобразования. После проверки права
выдачи приложение подписывает точный путь CDN и запрос SigV4 к S3. Запрос к закрытому бакету
авторизуется при промахе. Ключ кеша не зависит от параметров подписей.

Для оригинала приложение проверяет право просмотра или скачивания при выдаче короткой ссылки
CDN. При промахе CDN обращается к маршруту Django с секретным заголовком. Django читает точный
объект из приватного бакета оригиналов и передаёт его потоком с поддержкой байтовых диапазонов.
CDN проверяет подпись при каждом обращении, включая попадание в кеш. Просмотр и скачивание
используют отдельные пути кеша, чтобы выдавать соответствующий `Content-Disposition`.

В Git хранится конфигурация источников, правил маршрутизации, кеширования и HTTPS. Секреты
берутся из Lockbox. Правила видимости галерей, выбора водяных превью и выдачи оплаченных
оригиналов сохраняются.

## Последствия

Обычный и водяной JPEG передаются в сохранённом размере. Попадания в кеш исключают повторное
чтение тела из S3. При выдаче ссылки через отдельный маршрут Django сохраняется `HEAD` в S3
для проверки объекта и аудита оригиналов. Галерея выпускает ссылки на готовые превью из
сохранённых ключей без `HEAD`. При промахе по оригиналу `GET` и передача тела занимают
сетевую и серверную ёмкость ВМ приложения.
При отзыве права Django перестаёт выдавать новые ссылки. Время жизни ранее выданной ссылки
ограничено сроком её подписи.

Перед включением проверяем фактическую передачу SigV4 до S3, общий кеш для двух действующих
ссылок, отказ по недействительной подписи на прогретом кеше, запрет прямого обращения к
маршруту оригинала и скачивание с корректным именем и диапазоном. Эффект измеряем по чтениям
Object Storage и нагрузке Django на промахах по оригиналам.
