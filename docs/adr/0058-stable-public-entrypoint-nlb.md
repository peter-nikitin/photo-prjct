# 0058: Сохранять публичный адрес при изменении вычислительных ресурсов

- Status: Accepted
- Date: 2026-10-25
- Deciders: владелец проекта; явно принял ADR 0056, 0057, 0058 и 0063 в обсуждении 2026-10-25
- Supersedes: none; дополняет [0007](0007-nginx-certbot-https-edge.md) расположением публичного входа
- Superseded by: none

## Контекст

Владелец должен иметь возможность заменять VM, менять её размер и зону, сохраняя
публичный адрес сайта и CDN origin. Прямой публичный адрес VM связан с зоной;
текущий переезд в `ru-central1-d` проявляет эту зависимость. Задача — отделить
публичную идентичность сервиса от вычислительного ресурса. Непрерывное обслуживание
во время замены единственной VM в эту задачу не входит.

## Мотивы

- Отделить публичный IP от жизненного цикла backend.
- Сохранить существующий HTTPS edge Nginx/Certbot.
- Не оплачивать L7-функции, которые сейчас не нужны.

## Варианты

1. Прямой IP новой VM с обновлением DNS при смене адреса/зоны.
2. Application Load Balancer с L7-маршрутизацией и TLS termination.
3. Network Load Balancer с TCP forwarding к единственному backend.

## Решение

Публичная точка входа имеет собственный жизненный цикл и сохраняется при изменении backend.
Выбран вариант 3: NLB даёт нужное отделение на уровне TCP и оставляет существующее
завершение TLS на Nginx. Прямой IP дешевле, но не удовлетворяет требованию независимости
от зоны VM. ALB также отделяет вход от backend, однако его L7-функции сейчас не требуются
и увеличивают постоянную стоимость. Дополнительные расходы NLB приняты ради стабильного адреса.

### Следствия для реализации

Существующий зарезервированный `111.88.151.64` закрепляется за NLB;
TCP 80/443 направляются на внутренний IP VM. TLS, выбор virtual host и ACME остаются
на Nginx/Certbot. Frontend IP/NLB и backend target имеют независимый жизненный цикл.
Готовность backend подтверждает внутренний HTTP endpoint с проверкой БД.

Для исходящего интернета и прямого SSH VM имеет отдельный служебный public IP.
Он не используется в публичных DNS-записях сайта и может меняться при замене VM.

## Последствия

Замена backend не требует смены публичного адреса. Появляются постоянная стоимость NLB,
второго public IP и расходы обработки трафика; они включаются в review инфраструктуры.
Одна VM не получает HA: её остановка прерывает обслуживание. Target VM не должна
проверять себя через публичный NLB, поэтому локальная и внешняя проверки разделены.

## Проверка

Проверить сохранение frontend IP в plan замены/смены зоны backend, фактическую привязку
новой VM, Host/SNI, TLS/ACME и 503 при недоступной БД. Дорогая вторая VM только ради
демонстрации стабильности IP не требуется.
