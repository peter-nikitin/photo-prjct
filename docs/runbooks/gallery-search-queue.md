# Общая очередь поиска по лицу

`gallery-search-worker` работает на одной VM из того же `APP_IMAGE`, что web. Он последовательно
обрабатывает задачи из общей таблицы PostgreSQL. Поиск по фото ставится сразу в эту очередь.
Для селфи ML-воркер сначала получает вектор и возвращает его через закрытый callback, который
ставит задачу в общую очередь. [ADR 0066](../adr/0066-store-vectors-in-face-search-queue.md)

## Выпуск

`deploy/apply-deployment.sh` останавливает исполнитель с `--timeout 0` и web перед `migrate`.
После миграции и static web проходит обычный `--wait`, затем запускается исполнитель.
SIGTERM завершает исполнитель немедленно. При запуске прерванные задачи возвращаются в очередь.
Ранее принятые задачи галереи переносятся в общую очередь при обновлении схемы. Формат запроса
и ответа callback позволяет выполнить выпуск без синхронного обновления ML-воркеров.

Исполнитель записывает совпадения, переводит поиск в итоговый статус и завершает задачу
очереди в одной транзакции. Пользователь может открыть результат после коммита. Временное селфи
остаётся в закрытом хранилище до фонового удаления. Ansible запускает команду
`delete_temporary_selfies` раз в минуту в контейнере web, до десяти снимков за запуск.
При сбое хранилища запись сохраняет ключ для повторной очистки. Время до готовности
заканчивается на публикации. Подтверждение удаления хранится отдельно.

В локальном Compose очистку можно запустить командой
`docker compose exec -T web python manage.py delete_temporary_selfies --batch-size 10`.

Физические копии PostgreSQL в Cloud Backup могут содержать векторы в пределах действующей
политики хранения. Штатные логические выгрузки исключают содержимое таблицы
`selfie_search_facesearchtask`.
Восстановленная логическая копия сохраняет опубликованные результаты. При создании локального
клона скрипт останавливает web и исполнитель и удаляет из восстановленной БД ссылки на временные
снимки production. Незавершённые поиски с отсутствующим входом завершаются с ошибкой. При сбое
выпуска остановите приём и исполнитель, сохраните БД и выпустите исправление вперёд.

## Управление

Команды выполняются из каталога выпуска. На VM работает один экземпляр исполнителя.

```sh
docker compose --project-name photo-prjct --env-file .env -f docker-compose.deployment.yml ps gallery-search-worker
docker compose --project-name photo-prjct --env-file .env -f docker-compose.deployment.yml logs --tail 100 gallery-search-worker
docker compose --project-name photo-prjct --env-file .env -f docker-compose.deployment.yml stop --timeout 0 gallery-search-worker
docker compose --project-name photo-prjct --env-file .env -f docker-compose.deployment.yml start gallery-search-worker
```

Watchdog даёт ранжированию и записи результата до 150 секунд. При превышении бюджета
процесс завершается кодом 124.
Лимит SQL-ранжирования составляет 120 секунд и сокращается до оставшегося срока задачи для селфи.
Ошибка по лимиту SQL завершает поиск. Временная ошибка допускает до трёх попыток с интервалом
пять секунд. Пустая очередь опрашивается
с backoff 2–30 секунд. Ресурсы контейнера — 0.5 CPU, 256 MiB и 32 PID.

Ansible устанавливает почасовое удаление до 500 завершённых задач. Для ручного удаления одной
пачки используйте:

```sh
docker compose --project-name photo-prjct --env-file .env -f docker-compose.deployment.yml exec -T web python manage.py prune_face_search_tasks --batch-size 500
```

Очистка оставляет готовые результаты и времена этапов в записях поиска.

## Метрики времени

Дашборд показывает размер очереди с отложенными повторами и среднее время по этапам за пять минут.
Для галереи измеряются ожидание первого запуска и обработка до готовности. Для селфи
измеряются ожидание распознавания, распознавание, ожидание SQL-поиска и поиск с публикацией.
Слои строятся по одним и тем же успешно завершившимся поискам с полными замерами. Без таких
завершений в окне точек времени нет. Счётчики сохраняются между перезапусками и после очистки
очереди. Алерт `ReadyWorkStalled` различает ожидание распознавания селфи и ожидание SQL-поиска.

Отдельные графики p75 для галереи и селфи показывают время от постановки до готового
результата по успешным поискам за последние 24 часа. При пустой выборке значение отсутствует.
