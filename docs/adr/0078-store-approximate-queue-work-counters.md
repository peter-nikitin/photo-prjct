# 0078. Хранить приблизительные остатки всех очередей в PostgreSQL

- Status: Accepted
- Дата: 2026-11-20
- Авторы решения: владелец проекта

## Контекст

Оператору нужен общий обзор незавершённой работы и разрез по обработчикам фото.
Диагностика готовности к захвату охватывает только часть работы. Задачи в обработке,
ожидающие времени повтора или приостановленные тоже влияют на срок выполнения.

## Рассмотренные варианты

1. Считать остатки из продуктовых таблиц при каждом опросе. Стоимость запроса
   растёт вместе с очередью, даже если число серий остаётся постоянным.
2. Считать дельты в памяти коллектора по уведомлениям. После перезапуска
   требуется прочитать состояние очередей для восстановления остатков.
3. Хранить приблизительные остатки в PostgreSQL и менять их после продуктового
   коммита, как в [ADR 0072](0072-store-approximate-photo-import-counters.md).

## Решение

Храним строку на семейство очередей и дополнительные строки по типу обработчика фото.
Отслеживаем ожидающие, обрабатываемые, отложенные на повтор и приостановленные задачи.
Владельцы очередей определяют переходы состояний. После коммита они применяют
знаковые дельты отдельными короткими транзакциями с ограниченным ожиданием блокировок.

Опрос читает таблицу счётчиков. До инициализации и при сбое чтения коллектор
показывает недоступность наблюдения. Ручное заполнение читает индексируемые активные
состояния. Оператор запускает его при первом выпуске или для исправления погрешности.
Автоматических обходов и сверок нет.

Метрики готовности к захвату продолжают обслуживать свои диагностические сценарии.
Для каждой успешно завершённой задачи обработки фото владелец публикует длительности
ожидания до первого захвата и работы после него по механизму
[ADR 0067](0067-aggregate-queue-telemetry-from-completion-events.md).

## Последствия

- Остатки переживают перезапуск коллектора. Стоимость опроса зависит от числа очередей
  и типов обработчиков.
- Ошибка записи телеметрии сохраняет результат обработки и может оставить погрешность.
  Параллельные изменения очередей во время ручного заполнения также влияют на точность.
- Новый обработчик появляется в разрезе после первой постановки задачи через общий
  жизненный цикл обработки фото.
