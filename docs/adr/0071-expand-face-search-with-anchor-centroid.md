# 0071: Расширять поиск по лицу по центроиду прямых совпадений

- Status: Proposed
- Дата: 2026-11-19
- Решение принимает владелец проекта
- Заменяет при принятии: полностью [ADR 0070](0070-expand-face-search-from-direct-matches.md),
  частично [ADR 0019](0019-use-public-event-selfie-search.md) и
  [ADR 0022](0022-use-numbered-gallery-pages.md) только в части порядка показа
  готовых результатов поиска по лицу.
- Заменено: нет

## Контекст

При расширении по ADR 0070 PostgreSQL ищет совпадения от отдельных опор и сохраняет
свидетельство от лучшей из них. При нескольких согласованных опорах каждое лицо можно
сравнивать с их общим направлением. В архивном эксперименте на московском корпусе
центроид дал 531 добавление против 442 у каскада. На 96 запросов пришлось только
10 различных наборов прямых совпадений. Большинство добавлений не размечено,
поэтому эти числа описывают размер выдачи и не оценивают точность метода.

## Мотивы

- Использовать информацию нескольких ракурсов в одном точном поиске.
- Сохранять проверяемое происхождение каждого дополнения и смысл готовых выдач.
- Удерживать прежние границы мероприятия, доступности кадров, времени и обращения
  с биометрическими данными.

## Рассмотренные варианты

1. Сохранить поиск по отдельным разнообразным опорам. Каждый ракурс сохраняет
   собственный вклад, а число сравнений растёт с числом опор.
2. Искать по одному центроиду из ближайших согласованных опор. Общий вектор
   объединяет ракурсы и задаёт одну точку сравнения для корпуса.
3. Выполнять оба поиска. Объединение расширяет набор кандидатов и увеличивает
   нагрузку и сложность проверки качества.

## Решение

Предлагается вариант 2. Кандидатами в опоры становятся прямые совпадения с
косинусным расстоянием до исходного лица не выше 0,38. Кандидату требуется
ровно одна детекция в принятой попытке обработки, включая отклонённые по качеству.
Исходный кадр запроса из галереи исключается. Среди кандидатов, упорядоченных
по расстоянию до исходного лица, ID фото и UUID детекции, берутся до пяти
ближайших на расстоянии не выше 0,35 до первой опоры. PostgreSQL нормализует
каждый вектор, вычисляет среднее и нормализует его. В среднем участвуют только
выбранные опоры.
Одна опора задаёт своё направление. При отсутствии опор расширение пустое.

PostgreSQL выполняет один точный поиск среди доступных фотографий того же
мероприятия по прежнему порогу 0,42. На каждом новом кадре выбирается ближайшее
лицо. Во внутреннем порядке снимка центроидные совпадения следуют за прямыми
и кластерными. Они сами не участвуют в выборе опор. Прямой поиск по AdaFace,
общая очередь и срок хранения временного селфи сохраняют действующее поведение.
Центроид вычисляется внутри запроса. Значения параметров расширения исключаются
из журналов ошибок.

Для каждого добавленного кадра атомарно сохраняются совпавшая детекция,
расстояние до центроида и упорядоченные ссылки на все использованные прямые
свидетельства того же поиска. Для ранее сохранённых выдач остаются исходное
расстояние и единственная опора. Пересчёт готовых выдач не требуется.

Публичная выдача сортирует сохранённые кадры всех источников по возрастанию
времени съёмки. Кадры без времени показаны в конце. При одинаковом или
отсутствующем времени кадры сортируются по возрастанию ID фото. Один порядок
применяется на всех страницах, включая ранее сохранённые выдачи. Внутреннее
ранжирование определяет совпадения и опоры.

Хронология применяется при чтении снимка. По ADR 0019 состав и сохранённый
`rank` снимка фиксируются, а текущая доступность кадров проверяется при показе.
Нумерацию и размер страниц, обычный листинг галереи и доступ к медиа
регулирует ADR 0022.

## Последствия

Точный поиск выполняется по одному центроиду при любом числе опор. Для каждого
дополнения появляется до пяти ссылок на прямые свидетельства. Усреднение может
изменить состав выдачи в обе стороны. Качество опор зависит от детектора,
а близость к первой опоре сама по себе не подтверждает личность.

## Проверка и откат

Сверить SQL с экспериментом на сохранённых корпусах в пределах численного
допуска ADR 0041. Перед публичным включением оценить состав дополнений на
размеченных поисках, время выполнения и ошибки в режиме `staff` существующего
флага `face-search-anchor-expansion`. Состояние `off` отключает центроидное
расширение. После записи нескольких опор для одного совпадения переход на
старый образ требует согласованного восстановления базы.
