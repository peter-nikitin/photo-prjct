# FindMe Photo

FindMe Photo — площадка фотографий с мероприятий. Гости находят снимки по номеру участника,
лицу и данным мероприятия; фотографы и операторы загружают, проверяют и публикуют фотографии.
Доступ к закрытым оригиналам определяется правилами галереи и подтверждённой покупкой.

## Локальная разработка

Нужны Git, Docker с Compose и Python 3.12+. Для задач с JavaScript понадобятся NVM и Node 22.
После клонирования репозитория подготовьте `.venv` в основном checkout:

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
```

Проверки запускайте через локальную `.venv`, без глобальных pytest, Ruff и mypy.

Новый worktree создаётся **только из основного checkout**:

```bash
make worktree NAME=my-change
cd .worktrees/my-change
```

По умолчанию исходная точка — `origin/main`; при необходимости укажите `BASE=<ref>`. Команда
создаёт ветку `codex/<name>`, подключает общую `.venv`, устанавливает hook и создаёт собственную
тестовую `.env` в worktree. Секреты из `.env` основного checkout не копируются. Для уже созданного
checkout восстановите hook командой `make hooks`.

Без доступа к облачным секретам можно запускать каталог и Django Admin с локальной базой и
файловым хранилищем. В новом worktree уже есть тестовая `.env`: перед запуском Compose измените
в ней `DB_HOST=localhost` на `DB_HOST=db`, поскольку контейнер `web` обращается к контейнеру базы
по имени сервиса. Остальные значения оставьте из созданной тестовой `.env`; реальные секреты не
нужны. Функции, требующие Object Storage, обработки, импорта или оплаты, в таком режиме не
проверяются. Затем выполните из worktree:

```bash
docker compose up --build -d db web
docker compose logs -f web
```

Если для локальной разработки нужны облачные секреты, запросите у ответственного доступ к
конкретному секрету проекта в Yandex Lockbox: права `lockbox.viewer` и
`lockbox.payloadViewer` выдаются на сам секрет, а не на всю папку. Настройте личную авторизованную
сессию `yc` и запустите **из изолированного worktree**:

```bash
make local-web
```

Команда берёт разрешённый набор значений Lockbox для `local-web`, применяет локальные настройки
и запускает `db` и `web`. Она не требует копировать секреты в `.env` и не выводит их в терминал.
Если доступа нет, продолжайте работу без секретов или запросите выдачу указанных прав; детали
доступа и проверки описаны в [runbook секретов](docs/runbooks/environment-secrets.md) и
[манифесте окружения](docs/runbooks/environment-secrets-inventory.md).

Приложение: <http://localhost:8000/>; Django Admin: <http://localhost:8000/admin/>.
При первом запуске создайте администратора командой
`docker compose exec web python manage.py createsuperuser`. Локальный entrypoint сам применяет
миграции, создаёт группу фотографов и собирает статические файлы.
Остановите запущенные контейнеры из того же checkout командой `docker compose down`. Она сохраняет
том PostgreSQL. Основной checkout и worktree используют разные проекты Compose, но одинаковые
локальные порты `5432` и `8000`; одновременно запущенным версиям нужны разные порты.

Подготовка JavaScript-зависимостей:

```bash
nvm install
nvm use
npm ci
```

Версия `node` должна быть `v22.x.x`, как в `.nvmrc` и CI.

## Проверки

```bash
make test
make test TESTS="tests/test_repository_foundation.py"
make static
make check
```

`make test` запускает основные Python-тесты, `make static` — форматирование, lint и mypy,
`make check` — полный обязательный набор. Дополнительные слои и правила их выбора описаны в
[документе о тестировании](docs/testing.md). Перед передачей изменений в Python запустите
`.venv/bin/pre-commit run --files <изменённые Python-файлы>`.

Для локальной проверки реального Object Storage используйте
[проверку фотообработки](docs/local-photo-processing-check.md). Копирование данных развернутой
базы в **локальную** базу для разработки миграции выполняет `make db-clone-deployed`;
команда заменяет только локальную базу и требует явного подтверждения. Она не является резервным
копированием сервиса.

## Развёртывание и эксплуатация

Один канонический сервис работает на VM в Yandex Cloud. Workflow **Deploy** реагирует на изменения
`main`: изменения приложения и worker образов выпускаются раздельно. При изменении только
документов workflow запускает классификацию, но пропускает сборку и выкладку. Подробный порядок
подготовки, проверки и восстановления находится в
[runbook развёртывания](docs/runbooks/deployment.md). Состояние пула обработчиков и его выпуск
описаны в [отдельном runbook](docs/runbooks/worker-pools.md).

Секреты задаются через утверждённый манифест и Yandex Lockbox; локальные `.env` не входят в Git.
Действующие процедуры для секретов, мониторинга, поиска по селфи и импорта собраны в
[указателе операций](docs/operations.md). Наличие кода, успешный CI, успешное развёртывание и
наблюдаемая работа функции — разные уровни доказательств; статус конкретной возможности
проверяйте по реестрам задач и операционным свидетельствам.
