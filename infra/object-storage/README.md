# Параметры бакетов приложения

[ADR 0068](../../docs/adr/0068-separate-originals-event-media-and-operational-storage.md)
определяет три независимых роли. Приложение после переключения получает имена из переменных
`ORIGINALS_S3_BUCKET`, `OPERATIONAL_S3_BUCKET` и `EVENT_MEDIA_S3_BUCKET`.
Deploy image origin использует то же `EVENT_MEDIA_S3_BUCKET`.

Три бакета, политики доступа, CORS и lifecycle описаны в [Terraform](../terraform/media_storage.tf).
Рабочие имена формируются по ADR 0068 с суффиксом из ID каталога. Выход
`media_storage_buckets` содержит имена для этапа переключения. Действующие сервисные
аккаунты и origin CORS заданы в [project.tfvars](../terraform/project.tfvars).

| Бакет | Настройка и права |
| --- | --- |
| `findme-photo-media-originals-prod-b1g2qttg` | Приватный. Учётная запись приватных медиа читает и публикует объекты `originals/`. У операций отката загрузки есть право удалить свой неподтверждённый объект. Deploy записывает новые оригиналы в `COLD`. |
| `findme-photo-media-scratch-prod-b1g2qttg` | Приватный `STANDARD` без версионирования. Учётная запись приватных медиа работает с `uploads/`, `preview-jobs/` и `selfie-search/`. CORS для загрузок находится здесь. Lifecycle удаляет оставшиеся `preview-jobs/` через семь дней и `selfie-search/` через один день. Каждый процесс удаляет созданные им временные файлы. Lifecycle страхует очистку превью и селфи. Срок для брошенных загрузок определяется состоянием партии. |
| `findme-photo-media-delivery-prod-b1g2qttg` | `STANDARD`, общие флаги анонимного доступа выключены. Учётная запись приватных медиа публикует и читает `previews/`. У image origin есть отдельное право чтения этого префикса. Учётная запись обложек пишет только в `event-covers/`. При сохранении обложке назначается объектный ACL `public-read`. |

Terraform управляет политиками всех трёх бакетов. У инфраструктурного CI роль
`storage.admin` в каталоге для создания бакетов и управления их настройками.
Для приложения используются три действующих сервисных аккаунта. На чтение
приватных объектов нужна подписанная ссылка, а публичная выдача обложек использует
ACL объекта. [Порядок проверки доступа](https://yandex.cloud/ru/docs/storage/security/overview).

Перед переключением проверяются наличие данных по ключам PostgreSQL, запрос CORS от реального
origin, публикация оригинала с ожидаемым классом, стандартный класс превью, выдача обложки без
токена, отказ для превью без токена и доступ с токеном, а также правила очистки временных файлов.
При инвентаризации постоянных объектов нужно учесть исторические ссылки `Photo.src`, если они
ещё используются. Порядок переноса данных и переключения рассматривается отдельно.

## Порядок выпуска

1. Проверить и согласовать сохранённый Terraform plan по [ADR 0057](../../docs/adr/0057-declarative-cloud-infrastructure.md).
   После слияния инфраструктурный workflow применяет согласованный план. Сверить CORS,
   lifecycle, `CopyObject`, чтение с подписью и публичный ACL на контрольных объектах.
   Действующее приложение продолжает использовать прежние настройки Deploy.
2. Перенести постоянные объекты и сверить ключи с PostgreSQL. При копировании готовых
   превью заменить префикс `derivatives/previews/` на `previews/`. В окне переключения
   обновить сохранённые ссылки на эти ключи и включить восстановление прежних ссылок в откат. Перед финальной сверкой
   остановить записи по старой схеме. Незавершённые загрузки, задачи обработки и поиск по селфи
   завершить или разобрать по отдельному плану переключения.
3. Заполнить новые переменные бакетов и выпустить приложение и image origin с новой схемой.
   Проверить галерею, обложки, скачивание, загрузку и поиск. На время проверки сохранить старые
   бакеты и комплект предыдущей конфигурации для отката.
4. После приёмки и окончания окна отката удалить прежние бакеты и старые переменные
   отдельной операцией.

До финального копирования в checkout приложения надо согласовать операции
с новыми префиксами и полномочиями. Управление политикой `delivery` остаётся в Terraform.
