# 0077: Раздельно включать вычисление внешности и расширение поиска

- Status: Accepted
- Дата: 2026-11-20
- Авторы решения: владелец проекта, явное требование отключаемого расширения
- Заменяет: нет
- Заменено: [ADR 0079](0079-require-enabled-apparel-search-to-complete.md) только в части публикации лицевой выдачи при ошибке включённой стадии одежды

## Контекст

Нужно проверять качество формы и нагрузку отдельно от базового поиска. На момент решения
в продовой базе больше 87 тысяч текущих состояний распознавания лиц и принятых превью.
Автоматическое добавление нового этапа ко всей истории загрузит общую CPU-ВМ.

## Мотивы

- Выкатить код без автоматического включения inference и новой выдачи.
- Мгновенно остановить расширение новых поисков, сохранив базовый путь.
- Отделить исторический backfill от приёма новых фотографий.

## Рассмотренные варианты

1. Один переключатель одновременно запускает индексацию и меняет выдачу.
2. Независимые code-owned gate для постановки обработки и использования признаков.
3. Запускать всё автоматически после миграции и откатывать образ при проблеме.

## Решение

Выбран вариант 2. `person-appearance-processing` управляет постановкой задач после принятия
нового превью. `apparel-search-expansion` управляет использованием готовых признаков в общем
исполнителе поиска. Оба определения поставляются в registry и создаются в `off` по ADR 0032.
Включение — отдельное действие в Admin; staff допускает проверку с серверным признаком
доступа. Gate обработки не означает автоматический обход истории.

При выключенном расширении выполняется существующий поиск по лицу без чтения таблиц
внешности и без inference. Необязательная стадия имеет ограниченный бюджет и собственную
границу отката: её ошибка не уничтожает уже полученный результат по лицу. Сохранённая выдача
остаётся снимком, выключение не переписывает историю.

Миграции только добавляют схему. Startup/reconcile не сбрасывают старые состояния и не
ставят всю историю в очередь внешности. Обработка не блокирует публикацию фото.
Выключение постановки останавливает новые задачи; оно не является отменой уже взятых lease.

Порядок приёмки: код и схема с off; совместимый worker и smoke; контролируемые новые фото;
проверка признаков; staff-поиск; разметка качества и отдельный нагрузочный прогон;
только затем решение о публичном включении. Для исторических мероприятий отдельно
оценивается локальный расчёт с импортом совместимых результатов, без запуска inference
на ВМ. Эта оценка не разрешает запись в прод или выдачу Mac прав промышленного worker.

## Последствия

### Положительные

- Поиск можно выключить независимо от сохранённых признаков и обработки новых фото.
- Выкладка не запускает массовый пересчёт исторических мероприятий.
- Качество и нагрузка имеют самостоятельные этапы приёмки.

### Отрицательные

- При включённом поиске и неполной индексации расширение охватывает только готовую часть.
- Выключение gate не возвращает CPU уже выполняемой задачи; нужен контроль очереди/lease.
- Администратору нужно различать два переключателя и сохранённые снимки результатов.

## Проверка и откат

Проверить off/missing/staff/on, сохранение прежних состояний gate, ноль обращений к внешности
при off, сохранение baseline при optional failure и апгрейд непустой БД без исторического
enqueue. Откатить сначала расширение, затем постановку; сохранить принятые признаки и
обычные лица. Не менять права и не удалять processing history.
