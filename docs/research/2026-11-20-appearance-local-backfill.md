# Локальный backfill внешности: оценка после реализации

Дата: 2026-11-20. **Расчёт на Mac и последующий импорт готовых результатов возможны.**
Inference на production VM для этого не нужен. В текущей поставке есть основной процессор
и ограниченная постановка по конкретному фото; отдельный офлайн export/import ещё нужно
реализовать. Исторический backfill и запись его результатов в прод не выполнялись.

## Что проверено

Новый production extractor с настоящими YOLOX-S, ReID и SCRFD запущен на 60 локальных
канонических превью: по 20 случайных кадров трёх мероприятий, seed `20261120`.
Все 60 результатов прошли тот же валидатор, что принимает worker API.
Из 258 фигур дескрипторы получили 124; отказ по деталям — 99, сильная размытость — 26,
смешанная резкость — 7, ограничение дескрипторов — 2. На этих кадрах нет превышения
контрактного payload; максимум около 162 КиБ.

Для тех же 60 кадров read-only запросом проверены текущие продовые accepted preview key,
SHA256, размеры и accepted attempt лиц/превью: расхождений с локальным manifest нет.
Лица этих 60 кадров рассчитаны по тому же превью. Это проверка выборки, не подтверждение
актуальности всех 51 629 фото: полный manifest нужно сверить непосредственно перед импортом.

На Mac Apple M5 Pro, arm64, OpenVINO 2025.4.0, один native CPU-поток: прогретый p50 около
187 мс/кадр, p95 около 230 мс. Декодирование и проверка хеша входят; загрузка моделей
отделена первым кадром. Для сравнения фильтра качества проверены все 59 зафиксированных
вырезок прежнего отчёта: совпали причины и те же 16 отклонений.
Это не измерение Linux VM, конкурентной нагрузки или полного импорта.

Это локальные корпуса из snapshot базы 2026-11-18 и резервных изображений 2026-10-13.
Существуют собственные manifests и результаты полной SHA256-проверки при сборке.
На остальных мероприятиях доступность локальных превью отдельно не проверялась.

Линейная экстраполяция средних времён по каждому мероприятию даёт примерно 2,8 часа
последовательного расчёта. Это ориентир по 60 кадрам: закладывать запас на сложные группы,
нагрев, сохранение пакетов и повторы; начать с одного небольшого мероприятия.
По объёму JSON этой выборки готовые результаты трёх корпусов составят около 2,1 ГБ
до сжатия. Фактический объём БД и WAL выше сырых векторов и требует отдельного измерения
при пробном импорте; свободный диск production этой оценкой не подтверждён.

## Почему старые embeddings нельзя просто загрузить

В старом индексе 185 925 ReID-векторов с прежним фильтром фона. Они не содержат полного
нового quality policy, привязки головы и набора дескрипторов принятого процессора.
Совпадение названия ReID-модели недостаточно для совместимости поколений.
Нельзя объявлять их принятыми новой конфигурацией или переписывать старые face attempts.
Надёжнее повторно рассчитать новый результат из уже сохранённых точных JPEG.

## Следующий ограниченный шаг

1. Экспортировать manifest одного события: photo/event, accepted preview attempt/key/SHA256,
   байты/размеры, актуальную конфигурацию процессора и привязку принятого face attempt.
2. На Mac проверить JPEG по manifest и выполнить **тот же** extractor. Сохранить результаты
   по фото с input fingerprint, model/config hash и checksum пакета; поддержать resume
   без повторного расчёта готовых файлов. Mac не нужны ключи worker API или права записи
   в production DB.
3. Сделать отдельную management-команду импорта с dry-run и явными event/batch limits.
   Импорт повторно проверяет актуальный preview, версию модели/конфигурации и строгий validator.
   Пакеты от изменившегося превью отклоняются; импорт повторяемый, не дублирует фигуры.
4. Принять пакет через отдельную проверенную операцию, создающую согласованные run/job/attempt,
   состояние и дескрипторы атомарно. Не подделывать lease, не записывать одну таблицу векторов
   и не включать автоматическую постановку: иначе VM-worker может забрать те же задачи.
5. Начать с малого ограниченного пакета, проверить read/search и рост БД/WAL, затем загружать
   остальное порциями с возможностью остановки. Расширение поиска при этом оставить `off`.

Импорт всё равно использует CPU/IO PostgreSQL и создаёт WAL; «не грузить VM» здесь означает
убрать ML-inference, а не нулевую стоимость записи. Проверку свободного диска, dry-run,
первый импорт и активацию выполнить отдельной операционной задачей после принятия команды.
