# Перенести S3-медиа в бакеты с каноническими именами

Дата: 2026-10-26. Статус: следующий этап, не блокирует восстановление сайта.

## Текущий объём

По решению владельца сайт восстанавливается с существующими бакетами:

- private media — `hires-staging`;
- public media — `findme-photo-public-media-b1g2qttg`;
- selfie feedback — `findme-selfie-feedback-staging-b1g2qttg`.

В текущем этапе не создаются новые media/feedback buckets, не копируются их объекты
и не удаляются действующие бакеты. Их исторические имена — явное исключение из нормализации.
Самостоятельный Terraform backend не является media bucket и рассматривается отдельно.

## Следующий этап

После восстановления доступности вернуться к именам `findme-photo-private-media`,
`findme-photo-public-media`, `findme-photo-selfie-feedback` с проверкой их доступности.
Действующие object keys, содержимое, значимые версии, metadata, cache/content headers,
права, CORS, lifecycle и нужное шифрование должны сохраняться. Источники private/public
не удаляются до полной сверки и переключения всех потребителей.

Ранее владелец разрешил не переносить старые неактуальные feedback-объекты. До будущей
миграции могли появиться новые данные: нельзя применить это разрешение ко всему будущему
содержимому без проверки его состава и актуальности. Сохранить consent, KMS и срок хранения.

Заново получить inventory и проверить наличие записей в момент миграции. Утверждение
«сейчас сайт не работает и записей нет» относится к восстановлению и не гарантируется
для следующего этапа. Тогда же выбрать необходимую финальную синхронизацию по фактическим
писателям, не строя её сейчас.

Оценить операции copy/check, возможный трафик и временное дублирование хранения до разрешения
платного исполнения. Использовать server-side copy; не достраивать прерванный локальный экспорт
как обязательную промежуточную копию. Старый `scripts/copy-object-storage-bucket.py` содержит
уже удалённый public source и требует отдельной актуализации на этом этапе.

## Условие завершения

Полная сверка выбранного inventory, подтверждённые чтение/запись и продуктовые пути
cover/preview/authorized original на новых бакетах; после этого — явно согласованное
удаление источников. Эта работа оформляется отдельным планом и ресурсными PR.
