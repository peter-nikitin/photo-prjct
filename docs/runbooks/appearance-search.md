## Раздельные переключатели

| Переключатель | Назначение | Начальное состояние |
| --- | --- | --- |
| `face-search-anchor-expansion` | Существующее расширение по лицевому центроиду | Сохранить состояние оператора |
| `person-appearance-processing` | Ставить новый этап после принятия чистого превью | `off` |
| `apparel-search-expansion` | Дополнять выдачу готовыми признаками внешности | `off` |

Состояния меняются только в Django Admin → Feature flags. Для обработки `staff` означает
явную постановку конкретного фото оператором; фоновый callback без пользователя работает
только при `on`. Для поиска `staff` проверяет серверный признак staff текущего запроса. Выключение поиска не удаляет
признаки и не меняет сохранённые выдачи. Выключение обработки не отменяет выполняемый lease.
Выкладка и reconcile не запускают массовую обработку исторических фотографий.

## Приёмка

1. Выкатить схему и совместимые образы с двумя новыми gate `off`. Проверить worker model smoke.
2. В `staff` явно поставить **одно** принятое превью командой
   `python manage.py enroll_person_appearance PHOTO_ID EXACT_ACCEPTED_PREVIEW_KEY`
   в web-контейнере; ключ взять из принятого `PhotoDerivative`, а не из оригинала.
   Проверить отдельное состояние внешности и рамки. Повторить на групповом кадре, закрытом
   лице и размытом фоне. При `on` новые превью ставятся автоматически, история не обходится.
3. Проверить причины `strong_blur`, `lack_details`, `mixed_sharpness`. Это оценка фигуры,
   она не удаляет фото или лица. Отклонённая фигура не имеет ReID/HOG/цветового дескриптора.
4. Для одинаковых запросов сравнить выдачу при выключенном расширении и в `staff`.
   Разметить добавления и рекомендации отдельно от исходных лиц. Отсутствие метки — неизвестно.
   Свидетельства: Admin → Selfie searches → поиск → «Решения поиска по внешности»;
   требуется право просмотра новой модели свидетельств.
5. Отдельно измерить полное время поиска и SQL, p50/p95, CPU/RSS исполнителя, CPU/IO БД,
   длину очереди и ошибки. Сравнивать одинаковые мероприятия и запросы с off и staff/on;
   inference при загрузке измерять отдельно. До публичного включения провести нагрузочный
   прогон в согласованных пределах. Внедрение само по себе не подтверждает качество или
   допустимую нагрузку на Linux CPU.
6. После оценки принять отдельное решение о публичном `on`. При проблеме сначала выключить
   `apparel-search-expansion`, затем при необходимости постановку обработки.

Сильное совпадение лица сохраняется: рекомендация убрать по форме не является автоматическим
удалением. Рекомендации не меняют ручную разметку и пороги.

## Как читать пороги

| Сигнал | Начальный порог | Смысл |
| --- | --- | --- |
| ReID | similarity ≥0,70 | Пригодность кандидата по индивидуальной опоре |
| Связанное лицо | distance ≤0,55 (similarity ≥0,45) | Дополнительная проверка при доступном лице той же фигуры |
| HOG шлема | similarity ≥0,68 | Дополнительная проверка при пригодных вырезках обоих шлемов |
| Резкость | энергия 400 | Нормализованный Лапласиан областей фигуры, не сходство |

Это исследовательские пороги текущей конфигурации. Обычный порог поиска по лицу —
**distance ≤0,42**, то есть similarity ≥0,58; 0,42 нельзя сравнивать напрямую с similarity.
Цвет используется отдельно от ReID, а отсутствие лица/шлема не означает несовпадение.

## Исторические мероприятия

Локальный расчёт проверен настоящим процессором на 60 случайных превью; их manifest совпал
с актуальной продовой выборкой. На 51 629 доступных локальных JPEG расчёт оценивается примерно
в 2,8 часа без учёта запаса и импорта. Нужен пересчёт старых экспериментальных embeddings
по новому контракту и отдельная проверяемая команда импорта; она ещё не реализована.
