# 0071: Собирать архивы фотографий в фоне

- Status: Accepted
- Дата: 2026-11-20
- Авторы решения: владелец проекта
- Заменяет: [ADR 0034](0034-stream-page-scoped-photo-archives-through-django.md)

## Контекст

Каждое архивное скачивание занимает поток Gunicorn от открытия оригиналов до окончания передачи.
Скорость соединения клиента влияет на доступную ёмкость веб-приложения.

## Варианты

1. Выделить сервис потоковой выдачи и сохранить немедленное начало скачивания.
2. Собирать архив в фоне и отдавать локальный файл через Nginx.
3. Собирать архив в фоне в закрытый Object Storage и отдавать его через CDN.

## Решение

Выбран третий вариант. При запросе Django авторизует точный набор фотографий открытой страницы,
записывает аудит для платного заказа и ставит задание в PostgreSQL. Пока отдельный процесс
собирает ZIP без повторного сжатия, клиент видит «Готовим архив…». Архив хранится в закрытом
временном бакете из [ADR 0068](0068-separate-originals-event-media-and-operational-storage.md).
Lifecycle очищает объекты под префиксом `archives/` через один день.

После принятия задания приложение выдаёт случайную ссылку на статус. Владение этой ссылкой
даёт доступ к архиву до истечения срока. При получении готового файла Django подписывает ссылку
CDN без повторной проверки исходного заказа, поиска или фотографий.

CDN проверяет подпись и срок на каждом запросе, включая попадания в кеш. При промахе CDN читает
ZIP из S3 по подписанному запросу. Запросы с разными действующими подписями используют общий
кеш объекта. Политика бакета отклоняет чтение архивов вне сетей Cloud CDN. Список сетей
версионируется вместе с политикой. Такой же принцип подписания используется для закрытых превью в
[ADR 0069](0069-serve-media-through-cdn-without-imgproxy.md).

Архив доступен целиком после успешной сборки. Повторный запрос на подготовку той же страницы
может использовать готовый ZIP. Для платного заказа сохраняется учёт отсутствующих оригиналов.

## Последствия

Потоки веб-приложения обрабатывают короткие запросы, а клиентский трафик скачивания идёт через CDN. Попадания в кеш обходятся без чтения из S3. Подготовка добавляет ожидание перед скачиванием, временную запись в PostgreSQL
и временную копию оригиналов. Число одновременных сборок ограничено независимо от Gunicorn.

## Проверка и откат

Перед выпуском применить согласованный Terraform plan для доступа и lifecycle бакета, затем
настроить правило CDN. В режиме staff проверить бесплатный результат и оплаченный заказ.
Подтвердить попадание в кеш для второй действующей ссылки, отказ без подписи на прогретом кеше,
отказ при обращении к S3 с той же подписью вне сетей CDN и выдачу ZIP по диапазонам.

При откате флаг `bulk-photo-download` останавливает новые запросы. Уже выданные ссылки
действуют до истечения срока. Остановка правила CDN прекращает выдачу и по этим ссылкам.
Lifecycle удаляет оставшиеся ZIP.
